# Write it in Go

## Context and problem statement

weightkeep needs to be a single static binary for Linux, macOS and Windows that embeds a BitTorrent
client with v2 (BEP 52) support and web seeds (BEP 19), an HTTP server, SQLite, and TUF/Sigstore
verification. Rust and Go were the realistic options.

## Decision drivers

- BitTorrent v2 and web seeds are core, not optional: v2 gives per-file SHA-256 merkle roots and
  cross-torrent deduplication, web seeds let the Hub act as a seed of last resort.
- Static cross-compilation without a C toolchain.
- Maturity of TUF and Sigstore libraries.

## Considered options

1. Rust with librqbit
2. Rust with libtorrent-rasterbar over FFI
3. Go with anacrolix/torrent

## Decision outcome

Chosen option: Go with `github.com/anacrolix/torrent`.

As of September 2026, librqbit (9.0.1) has neither v2 nor web seed support, and its v2 design issue
(#546) has no maintainer response. libtorrent is the reference implementation but makes static
cross-builds painful. anacrolix/torrent has hybrid v1/v2, web seeds with a pluggable HTTP transport,
custom storage, and builds with `CGO_ENABLED=0`. go-tuf v2 and sigstore-go v1 are stable; the Rust
equivalents are marked experimental. `modernc.org/sqlite` gives us SQLite without cgo.

A spike build (anacrolix + modernc sqlite + net/http, stripped) came out at 22-24 MB per platform.

### Consequences

- Good: one `go build` per target, GoReleaser for packaging (Homebrew, Scoop, winget, deb/rpm).
- Good: `net/http` covers the proxy; no framework.
- Bad: anacrolix/torrent is effectively maintained by one person and tags releases rarely. We pin a
  version, keep our use of it behind `internal/torrent`, and are prepared to vendor or fork.
- Bad: anacrolix cannot create v2 torrents, so we write our own hybrid torrent builder (see ADR 0005).
- Bad: the binary is larger than a Rust equivalent would be. Acceptable.

## More information

anacrolix/torrent is MPL-2.0. That is file-level copyleft and compatible with our Apache-2.0 code as
long as we publish changes to MPL files, which we would do anyway.
